# 报关申报要素自动校验 · 使用说明（README）

> 配套文档：`报关申报要素自动校验SOP.md`（完整作业规范）
> 本文件面向**使用者**，回答"怎么用、要准备什么、要注意什么"。

---

## 一、这个能力是做什么的

一句话：**自动核对出口报关申报要素里的「品牌」「型号」，与产品实拍标签上印的是否一致。**

它替代的工作是：人工逐份打开 Excel、翻共享盘找图、一张张肉眼看标签、手工记录差异。一个 60 条的票，人工要几天；自动化后 10–20 分钟。

**核心价值**：不是"扫一遍图片"，而是产出一份**带完整证据链、能直接交差的校验报告**——每条结论都能指回具体的图和具体的 OCR 原文。

## 二、使用前需要具备什么

### 2.1 硬性前置条件

| 条件 | 说明 | 没有会怎样 |
|---|---|---|
| **申报要素 Excel** | 含「出货通知书号 / 成品料号 / 订单号 / 申报要素」等字段 | 无法启动 |
| **标签图片** | 按 `{票号}\{料号}\` 组织的实拍图，文件名含料号与订单号 | 全部判"缺图" |
| **共享目录读权限** | 图片在共享盘时需域账号可读 | 路径访问失败 |
| **Python 3.11+** | 推荐 3.13 | 脚本无法运行 |
| **Python 依赖** | `openpyxl`、`rapidocr_onnxruntime`、`Pillow`、`numpy`、`opencv-python` | 缺哪个装哪个 |

### 2.2 数据组织要求

**Excel 侧**：至少包含以下信息
- 出货通知书号（用于定位票号文件夹）
- 成品料号（用于定位料号子目录）
- 订单号（用于区分同料号多订单）
- 申报要素文本（内含品牌、型号）

**图片侧**：推荐结构
```
{图片根}\{人员}\{出货通知书号}\{成品料号}[-后缀]\{料号}&{订单号}&{序号}.jpg
```

**容忍的结构变体**（脚本已适配，无需你调整）：
- 图片在 `{订单号}-0-{箱数}\` 子目录下 → 自动子目录兜底扫描
- 图片直接堆在票号根目录 → 按文件名解析
- 文件名非标（如 `{料号} (n).png`）→ 尽力解析

## 三、三步使用

### 方式一：放进默认目录（推荐）

```
1. 把申报要素 Excel 放进  项目空间\原始输入\
2. 告诉我：「执行申报要素比对」
3. 拿产物：项目空间\成果产出\ 下的两个文件
```

### 方式二：直接说明位置（无需移动文件）

```
1. 把文件留在原地
2. 告诉我：「执行申报要素比对，Excel 在 D:\xxx\申报要素-SA26090215.xlsx，
             图片在 \\服务器\...\SA26090215\」
3. 拿产物：项目空间\成果产出\ 下的两个文件

```

## 四、你会拿到什么

| 产物 | 位置 | 用途 |
|---|---|---|
| **校验汇总表_{票号}.xlsx** | `成果产出\` | 主交付物，13 列完整证据链，可直接交差 |
| **{票号}_待人工复核清单.csv** | `成果产出\` | 行动项清单，告诉你哪几条要人工看 |
| 校验详细日志.json | `过程产出\` | 追溯用，含每条的全部 OCR 原文 |

**汇总表的 13 列**（顺序固定，恰好 13 列）：

| # | 列名 | 说明 |
|---|---|---|
| 1 | 出货通知书号 | |
| 2 | 成品料号 | |
| 3 | 订单号 | |
| 4 | 中文品名 | |
| 5 | 申报品牌 | |
| 6 | 申报型号 | |
| 7 | 图片识别品牌 | |
| 8 | 图片识别型号 | |
| 9 | 校验结果 | 四类之一（✅ / ❌ / ⚠️ / 🔵） |
| 10 | **判定依据** | **每一条记录都有**：判定依据句 ＋ 差异明细（含逐字符差异）＋ 复核备注 |
| 11 | 证据（OCR 片段） | |
| 12 | 图片路径 | |
| 13 | 判定说明 | 一句话判定理由（与第 10 列首段同源） |

> ⚠️ **第 10 列「判定依据」不只在有差异时才有内容**（v0.3.6 起）。
> 早先这一列叫「差异备注」，✅ 校验合格的行整格为空 —— 合格记录拿不到依据、无法追溯。
> 现在**四类结论（成功 / 失败 / 质疑 / 缺图）都会写清依据**：
> 结论句在前，字符级差异点与人工复核备注在后。

## 五、必须遵守的规范

### 5.1 四条规范红线

| # | 规范 | 原因 |
|---|---|---|
| 1 | **用户指定优先** | 你说了位置就按你说的走，绝不擅自改回默认路径 |
| 2 | **原始输入只读** | 原始数据是审计依据，绝不允许修改、改名、删除 |
| 3 | **产物分流** | 最终交付物进 `成果产出\`，过程文件进 `过程产出\`，保持整洁 |
| 4 | **不虚高** | 疑似 OCR 噪声必须看图确认，绝不把假异常当真异常上报 |

### 5.2 目录空间规则

```
项目空间/
├── 原始输入/     🔒 只读，只进不改
├── 成果产出/     ✅ 最终交付物
├── 过程产出/     🔧 过程文件（可清理，但清了断点会丢）
└── 校验脚本.py
```

## 六、可能出现什么异常（14 条）

### 6.1 数据源类

| 现象 | 原因 | 处置 |
|---|---|---|
| 报"找不到 Excel" | 默认目录为空或命名不含"申报要素" | 显式指定路径 |
| 显式指定的路径报"不存在" | 路径拼写错 / 无权限 / 盘符未映射 | 核对路径与权限 |
| **跑出来的结果像是上一票的** | 默认目录里只有旧票数据，被误扫 | 显式指定本票 Excel 路径 |
| 图片全部报"缺图" | Excel 与图片目录结构不匹配（如无订单号列） | 检查票号/料号是否对应；脚本需适配新变体 |

### 6.2 解析类

| 现象 | 原因 | 处置 |
|---|---|---|
| 品牌解析为空但实际有 | 中文品牌 / 单"牌"字格式未覆盖 | 补规则 + 补回归用例 |
| 型号带脏尾（如 `A7A01G ，电视机用/`） | 分隔符变体、中文混入 | 补清洗规则 |
| Sheet 定位到错误的 Sheet | 变体结构（如 Sheet1 首列表头恰好叫"出货通知书号"） | 补 Sheet 定位规则 |
| 图片命中率异常低 | 列映射错位 / 结构变体未适配 | 停下修脚本，不要硬跑 |

### 6.3 执行类

| 现象 | 原因 | 处置 |
|---|---|---|
| 单批执行超时中断 | 图片多，超 2 分钟硬限制 | 缩批重跑（断点续跑不会重算已完成的） |
| 中文参数乱码 | 经 PowerShell 传中文 | 改用 Python 内设环境变量 |
| 子进程输出编码报错 | 未设编码 | 设 `PYTHONIOENCODING=utf-8` |
| 打包器读中文文件报错 | 打包器用 GBK | 用 `PYTHONUTF8=1` 强制 UTF-8 |

### 6.4 产物类

| 现象 | 原因 | 处置 |
|---|---|---|
| 在 `成果产出\` 找不到结果 | 任务未真正跑完（中途失败） | 检查 `过程产出\` 日志定位断点 |
| 断点丢失导致重跑 | `过程产出\` 被清理 | 确认无需保留后重跑，或禁止清理 |
| 复核清单"问题说明"显示异常（如以"零"开头） | 修正脚本取值 bug | 修脚本（注意值是否为真元组）后幂等重跑 |

## 七、自我进化

**怎么触发**：任务交付后，对我说「**复盘**」/「**总结**」/「**梳理**」

**会发生什么**：
1. 回顾本次执行，识别新变体、新噪声模式、新陷阱
2. 核实证据（对照日志，剔除孤例）
3. 更新规则文档与脚本，版本号递增
4. 跑回归测试确保不破坏既有能力
5. 给你一份进化报告

**四条护栏**：口径变更需你确认、版本必递增、改脚本必回归、无沉淀如实说。
