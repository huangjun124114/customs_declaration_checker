## 一、项目信息

| 项 | 内容 |
|---|---|
| Language | 中文 |
| Programming Language | Python 3.11+（推荐 3.13）+ PySide6（Qt for Python）原生桌面应用 |
| 打包方式 | PyInstaller 单文件 exe（`--onefile`），目标平台 Windows 11+ |
| 项目名（snake_case） | `customs_declaration_checker` |
| 交付形态 | 本地一键运行的单个 `.exe`，用户机器**无需安装 Python** |
| 输入 | ① 申报要素 Excel（.xlsx） ② 标签图片根目录（本地或 UNC 共享路径） |
| 输出 | ① 校验汇总表 `_{票号}.xlsx`（13 列） ② `{票号}_待人工复核清单.csv` ③ 校验详细日志 `.json` |

### 原始需求复述

用户（Jason）希望做一款**报关申报要素申报检验的小工具**，具备 GUI、本地一键运行能力，提供：
- 选择**图片目录**与 **Excel 文件**的入口；
- **进度日志**输出；
- 最终**结果 Excel 输出**的交互。

用户已明确的技术决策（已采信，不推翻）：
1. **技术路线**：Python + PySide6 原生桌面应用（单进程，直接调用现有 OCR / Excel 逻辑）。
2. **首版功能范围**：**核心闭环 + 人工复核工作台**。
   - 核心闭环：选 Excel + 选图片目录 → 一键跑 → 进度日志 → 输出校验汇总表；
   - 人工复核工作台：把 SOP 的 Phase 5–6（看图兜底 + 修正误判）搬进 GUI，提供"疑似噪声"的卡片式看图确认界面，人工改判后回写结果。
3. **交付形态**：PyInstaller 单文件 exe。

## 二、产品定义

### 2.1 产品目标（3 个正交目标）

| # | 目标 | 说明 | 可衡量指标 |
|---|---|---|---|
| **G1 提效** | 把报关申报要素校验从"人工逐份翻图"变为"一键自动化"，把作业时间从**几天压到 10–20 分钟** | 一个 60 条的票，人工要几天；自动化后 10–20 分钟（README 原文） | 60 条票全流程 ≤ 20 分钟；操作步骤 ≤ 5 步 |
| **G2 可信** | 输出一份**带完整证据链、能直接交差**的校验报告，守住"不虚高 / 不误放 / 可追溯"三条质量红线 | 每条结论都能指回具体的图和具体的 OCR 原文 | 100% 记录含 OCR 原文与图片路径；疑似噪声 0 条被直接上报为异常 |
| **G3 可用** | 让不懂脚本的报关/仓储物流同事也能**零代码、零配置**完成一次校验 | 双击 exe → 选两个路径 → 点开始 → 拿结果 | 全新用户 5 分钟内独立完成一次跑批；无 Python 环境依赖 |

### 2.2 价值主张

> **不是"扫一遍图片"，而是一份带完整证据链、能直接交差的校验报告。** 工具替代的是"人工逐份打开 Excel、翻共享盘找图、一张张肉眼看标签、手工记录差异"的高强度重复劳动；并通过 **"可疑的绝不硬判、一定让你看图确认"** 的产品化设计（人工复核工作台），把 SOP 里最核心的"不虚高"红线落到界面交互上。

### 2.3 目标用户与使用场景

| 用户角色 | 描述 | 核心诉求 |
|---|---|---|
| **主用户：报关/仓储物流同事** | 日常负责出货前/后报关单证核对，不写代码，需要拿到可直接交差的结果 | 操作简单、结果可信、能快速定位该人工看哪几条 |
| **复核者：报关主管/合规岗** | 对异常与疑似噪声做最终人工确认与改判，对结果负合规责任 | 能看图核对、能改判、能留痕、能导出 |
| **部署者：IT/实施** | 初次分发 exe、核对共享盘读权限 | 免安装、路径可配置、报错信息明确 |

**主要使用场景（报关单出货前/后校验）**：
1. **出货前预检**：报关同事拿到一票申报要素 Excel，跑一遍校验，在出货前发现品牌/型号申报与实拍标签不符的问题。
2. **出货后复核**：对已申报的票做一次完整校验，产出带证据链的汇总表，供审计/合规留档。
3. **跨票批量作业**：一天多票，逐票跑，产物按票号落盘到"成果产出"。
4. **人工兜底确认**：跑完后对"疑似 OCR 噪声"的记录，在工作台看图逐条确认并改判。

### 2.4 用户故事（按角色分组）

**A. 报关/仓储物流同事（操作者）**
- **US-01** 作为报关同事，我希望**在一个界面里分别选择 Excel 文件和图片根目录**，以便不用记脚本路径、不用改代码就能开始一次校验。
- **US-02** 作为报关同事，我希望**点一个"开始"按钮就自动完成全流程**（解析 → 匹配 → OCR → 判定 → 出表），以便把精力放在看结果而不是盯过程。
- **US-03** 作为报关同事，我希望**实时看到进度（当前第几条/共几条）和滚动日志**，以便知道工具在干活、大约还要多久，卡住时能定位问题。
- **US-04** 作为报关同事，我希望**在处理中途可以暂停/中止**，以便临时要去处理别的事或发现路径选错时能及时叫停。
- **US-05** 作为报关同事，我希望**跑完直接拿到一份校验汇总表 xlsx 和一份待人工复核清单**，且能一键打开输出目录，以便立刻进入下一步处理。
- **US-06** 作为报关同事，我希望**进度页能显示四类结果的实时计数**（合格 / 异常 / 缺图内标识 / 缺图），以便跑完前就心里有数。

**B. 复核者（报关主管/合规岗）**
- **US-07** 作为复核者，我希望对**"疑似噪声 / 证据不足"的记录打开一张卡片，左边看图片、右边看 OCR 原文与申报值对照**，以便像 SOP Phase 5 那样"看图兜底"，而不是把假异常当真异常上报。
- **US-08** 作为复核者，我希望**在卡片上直接改判（合格/异常/缺图内标识/缺图）并填写备注**，以便把我的人工结论回写到结果中（对应 SOP Phase 6 修正误判）。
- **US-09** 作为复核者，我希望**改判是幂等可重跑的**（同一记录重复改判以最后一次为准），以便修正过程可反复进行不产生脏数据。
- **US-10** 作为复核者，我希望**改判后的结果能重新导出为汇总表/复核清单**，以便交付物反映最终人工结论。

**C. IT/实施（部署者）**
- **US-11** 作为实施人员，我希望**exe 在用户机器上免安装、双击即用**，以便快速分发给不写代码的同事。
- **US-12** 作为实施人员，我希望**共享盘路径不可达时工具给出明确报错**（而不是中途崩溃或结果串票），以便我快速判断是权限还是路径问题。

## 三、技术规范

### 3.1 需求池（P0 / P1 / P2）

> 优先级定义：**P0 = Must have**（首版核心闭环，缺失则不可交付）；**P1 = Should have**（首版争取，含人工复核工作台关键能力）；**P2 = Nice to have**（后续迭代）。

#### P0 · 核心闭环（Must have）

| 编号 | 需求 | 描述 | 验收标准（Acceptance Criteria） |
|---|---|---|---|
| **FR-001** | 选择 Excel 文件 | 提供"选择 Excel"入口，支持浏览本地与 UNC 路径选择 .xlsx；选定后显示完整路径；用户显式指定优先于任何默认约定 | 选定后路径回显正确；选择不存在的路径时报错并**不进入**后续步骤；**绝不因未指定就盲目扫描默认目录** |
| **FR-002** | 选择图片根目录 | 提供"选择图片根目录"入口，支持本地目录与 UNC 共享目录（如 `\\172.20.99.220\...`） | 选定后路径回显正确；UNC 路径可选；不可达时给出显式报错 |
| **FR-003** | 数据源预校验 | 在开始前校验 Excel 与图片目录的存在性/可读性（对应 SOP Phase 0 数据源裁定） | 任一输入不存在/无权限时，**开始前**弹出明确错误提示（含路径），不进入跑批；不得中途崩溃 |
| **FR-004** | 一键执行（核心闭环） | 点击"开始"后自动串行执行：Excel 结构探查 → 解析 → 图片三级索引匹配 → 全量 OCR → 判定 → 生成结果（对应 SOP Phase 1–4、7） | 无需人工干预即可从输入跑到产出三件套；流程口径与 SOP 一致 |
| **FR-005** | 结构化结果判定 | 按 SOP 四类口径输出结果：✅校验合格 / ❌校验异常 / ⚠️缺图内标识·人工复核 / 🔵缺图·人工复核；异常时**必须列出差异点** | 结果只属于上述四类之一；型号不一致时必须给出逐字符差异；"双方均为无/空"判合格 |
| **FR-006** | 进度显示 | 显示进度条 + "当前第 N 条 / 共 M 条" + 当前正在处理的料号/订单 | 进度随处理实时更新；条数与实际记录数一致 |
| **FR-007** | 滚动日志 | 实时滚动输出处理日志（含级别），支持日志级别过滤（INFO/WARN/ERROR） | 日志实时刷新不卡界面；过滤切换后立即生效 |
| **FR-008** | 结果总览计数 | 以卡片展示四类判定计数（合格/异常/缺图内标识/缺图），随处理更新 | 四类计数之和 = 已处理记录数；跑完计数 = 汇总表行数 |
| **FR-009** | 输出校验汇总表 | 生成 `校验汇总表_{票号}.xlsx`，含 **13 列**：出货通知书号、成品料号、订单号、中文品名、申报品牌、申报型号、图片识别品牌、图片识别型号、校验结果、**判定依据**、证据（OCR 片段）、图片路径、判定说明 | 文件生成于"成果产出"目录；13 列齐全；每行含证据（OCR 原文片段/图片路径）；**第 10 列「判定依据」对四类结论均不得为空**（v0.3.6） |
| **FR-010** | 输出待人工复核清单 | 生成 `{票号}_待人工复核清单.csv`（⚠️与🔵类记录的行动项清单，含问题说明与证据） | 清单内容 = 结果中 ⚠️ + 🔵 类记录；每条含问题说明与证据 |
| **FR-011** | 原始输入只读红线 | 工具任何情况下**不得写入/改名/移动/删除**用户选定的 Excel 与图片目录 | 代码层面对输入路径仅以只读方式打开；跑批前后输入文件哈希/修改时间不变 |
| **FR-012** | 产物分流 | 最终交付物 → "成果产出"；过程文件（详细 JSON 日志、断点文件）→ "过程产出"，两者分目录存放 | 汇总表与复核清单不出现在"过程产出"；JSON 日志与断点不出现在"成果产出" |
| **FR-013** | 详细日志落盘（可追溯） | 生成 `校验详细日志_{票号}_累积.json`，记录**每条记录的全部 OCR 原文 + 判定依据**，落"过程产出" | 每条记录均含全部 OCR 文本与判定依据；可据此复现判定 |
| **FR-014** | 结果导出与打开目录 | 提供"导出结果"（可另存汇总表到用户指定位置）与"打开输出目录"按钮 | 点"打开目录"能在资源管理器中定位到"成果产出"；导出可另存为 .xlsx |

#### P1 · 人工复核工作台 + 健壮性（Should have）

| 编号 | 需求 | 描述 | 验收标准（Acceptance Criteria） |
|---|---|---|---|
| **FR-015** | 人工复核工作台（卡片式看图） | 对"疑似 OCR 噪声 / 证据不足 / 缺图内标识 / 缺图"记录，提供卡片式界面：**左：图片预览（含缩放/切图）；右：OCR 原文 + 申报值左右对照**（对应 SOP Phase 5 看图兜底） | 卡片可逐条浏览；能直接查看该记录对应的实拍图；能同时看到申报品牌/型号与图片识别品牌/型号；图片加载失败有占位提示 |
| **FR-016** | 人工改判 | 在卡片上提供改判按钮（合格/异常/缺图内标识/缺图）+ 备注输入框，改判结果回写结果集 | 改判后该记录结果与备注立即更新；改判**幂等**（按 `出货号\|料号\|订单` key 赋值，重复改判以最后一次为准） |
| **FR-017** | 改判后重新导出 | 改判后可重新导出汇总表/复核清单，反映最终人工结论 | 重新导出的文件包含所有人工改判结果与备注；与 SOP"修正误判"口径一致 |
| **FR-018** | 疑似噪声标记与去虚高 | 工作台默认聚拢"疑似噪声/证据不足"记录，**不得**把疑似 OCR 噪声直接计为异常上报 | 疑似噪声记录默认落入 ⚠️ 待人工复核，并提供看图入口；无任何记录被跳过确认直接上报异常 |
| **FR-019** | 断点续跑 | 支持中断后从断点恢复，已完成键不回退（对应 SOP Phase 3 断点续跑） | 中断后重跑不重算已完成记录；断点文件落"过程产出" |
| **FR-020** | 异常/错误不崩溃 | 单条记录 OCR/解析失败不中断整批；UNC 不可达、权限不足给出显式错误提示 | 单条失败记录进日志并继续；路径不可达时给出明确错误文案，不中途崩溃、不串票 |
| **FR-021** | 运行期可暂停/中止 | 支持暂停与中止按钮，中止后已完成结果可正常落盘 | 暂停后进度冻结、可恢复；中止后已完成结果不丢失 |

**线框要点**：
- 主界面横向三区（①数据源 ②进度日志 ③结果总览），顶部数据源区固定在操作区最上方，减少滚动。
- 数据源区在开始前给出**预校验状态灯**（✓/✗），把 SOP Phase 0 的"路径存在性校验"前置到界面。
- 日志区提供**级别过滤**（对应 FR-007），默认显示 INFO 及以上。
- 结果总览四张卡片**与 SOP 四类口径一一对应**（黑话对齐：合格 / 异常 / 缺图内标识·复核 / 缺图·复核）。
- 复核工作台的**左图右证 + 左右对照**布局，是"看图兜底"（Phase 5）与"改判"（Phase 6）的界面化落点；改判按钮四选项 = SOP 四类口径。

### 3.3 非功能需求（必须遵守）

| 编号 | 类别 | 需求 |
|---|---|---|
| **NFR-01** | 只读红线 | **原始输入只读**：任何情况下不得写入、改名、移动、删除用户选定的 Excel 与图片目录（Jason 反复强调的硬原则） |
| **NFR-02** | 产物分流 | 最终交付物进"成果产出"，过程文件（详细 JSON 日志、断点、临时脚本）进"过程产出"，物理分目录 |
| **NFR-03** | 不虚高红线 | 疑似 OCR 噪声**不得直接上报为异常**，必须落入 ⚠️ 待人工复核并提供看图确认入口 |
| **NFR-04** | 可追溯 | 每条记录保留**全部 OCR 原文与判定依据**，并可定位到具体图片路径 |
| **NFR-05** | 路径兼容 | 支持 UNC 共享路径（如 `\\172.20.99.220\...`）；支持中文路径；路径不可达时**显式报错**而非中途崩溃 |
| **NFR-06** | 运行环境 | Windows 11+；PyInstaller 单文件 exe；用户机器**无需安装 Python** |
| **NFR-07** | 中文与编码 | 中文路径/参数不得乱码（统一在进程内设环境变量，不依赖命令行传中文）；子进程设 `PYTHONIOENCODING=utf-8`；打包设 `PYTHONUTF8=1` |
| **NFR-08** | 长任务健壮性 | 大批量 OCR 长任务不阻塞界面（后台线程/进程 + 进度回调）；单条失败不中断整批 |
| **NFR-09** | 口径一致性 | 判定口径、四类结果、防误提取规则、图片三级索引规则**必须与 SOP v2.0 完全一致**，不得自创口径 |
| **NFR-10** | 可维护性 | 用户显式指定优先于默认约定；配置（共享根含年份、输出落点）可修改，不硬编码 |

## 四、待确认问题清单（需用户/主理人拍板）

| # | 问题 | 背景 / 影响 | 我的建议（供参考） |
|---|---|---|---|
| **Q1** | 是否需要**断点续跑 UI**（可视化断点、恢复入口）？还是仅内部静默续跑？ | SOP Phase 3 有断点续跑机制，但用户诉求未提 UI。做 UI 增加复杂度 | 首版**静默续跑 + 日志提示**（P1 内部能力），不做独立断点管理 UI |
| **Q2** | 是否需要**多票批量**（一次跑多张 Excel）？ | 用户诉求是"选一个 Excel"，但日常可能多票 | 首版**单票**（P0），多票列 P2（FR-023）后续迭代 |
| **Q3** | 输出目录是否**强制**"成果产出/过程产出"分流？还是允许用户自定义两个目录？ | 用户诉求只说"最终结果 excel 输出"；SOP 有分流铁律 | 建议**默认强制分流**（满足 SOP 铁律），同时允许用户分别指定"成果产出""过程产出"两个目录；若用户只给一个目录，则工具在其下自动建两个子目录 |
| **Q4** | GUI 是否需要承接 SOP 的**环境变量接口**（`CUSTOMS_EXCEL`/`CUSTOMS_SHARE`/`MAX_RECORDS` 等）？ | 现有逻辑依赖环境变量；GUI 化后是否保留 CLI/环境变量兼容 | 建议 GUI 为主；内部仍保留环境变量通道（便于回归与自动化），但不作为用户主路径 |
| **Q5** | 首版是否要内置**OCR 引擎依赖**（rapidocr + onnxruntime + opencv）全打进 exe？体积会显著变大 | 单文件 exe 打包 OCR 依赖体积通常 200MB+；首次 OCR 模型加载耗时 | 建议**全内置**以保证"免安装、一键运行"，接受体积；需确认用户对 exe 体积/首次启动耗时的容忍度 |
| **Q6** | 人工复核工作台的**改判结果**是只影响导出文件，还是也要回写"过程产出"JSON 日志？ | 影响可追溯性与重跑 | 建议**同时更新结果集与导出**，JSON 日志另存一份"复核后"版本，保留原始版 |
| **Q7** | 复核工作台是否需要**直接看图判断"缺图"类**（🔵）？缺图类本质是没图可看 | 🔵 类需补图后重跑，工作台价值有限 | 建议工作台对 🔵 类只提供"标记待补图 + 备注"，不提供图片预览 |
| **Q8** | 是否需要**回归测试开关/入口**（SOP Phase 2 要求跑回归）？ | 面向同事的分发版是否需要暴露测试入口 | 建议**不暴露**给普通用户，作为开发/实施内部能力 |
| **Q9** | 日志与结果的**票号自动识别**：当 Excel 未显式给票号时，如何确定 `{票号}` 命名？ | 影响输出文件命名与目录定位 | 建议从 Excel 标题/列自动提取；提取不到则报错要求用户填"可选票号"（FR-022 提前到 P0） |
| **Q10** | 是否需要**国际化/多语言**？ | 用户为中文环境 | 建议**仅中文** |
